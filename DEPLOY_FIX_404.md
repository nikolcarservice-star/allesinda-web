# Как убрать 404 для удаления фото и счётчика сообщений

Если после редеплоя всё равно приходят 404 на:
- `GET https://api.allesinda.com/chat/unread/count`
- `DELETE https://api.allesinda.com/media/me/209`

значит на сервере крутится **старая версия бэкенда** без этих маршрутов. Ниже — что сделать по шагам.

---

## 1. Убедиться, что в репозитории есть новый код

Локально в проекте проверьте, что в коде есть эндпоинты:

- **Бэкенд:**  
  - В файле `backend/app/routers/chat.py` есть строка с `@router.get("/unread/count")`.  
  - В файле `backend/app/routers/media.py` есть строка с `@router.delete("/me/{media_id}"`.

Если их нет — подтяните последние изменения из репозитория (git pull / обновите ветку).

Затем **закоммитьте и запушьте** все изменения в ту ветку, из которой Coolify деплоит (обычно `main` или `master`):

```bash
git add .
git commit -m "Add chat unread count and media delete endpoints"
git push origin main
```

(Вместо `main` подставьте свою ветку.)

---

## 2. В Coolify открыть приложение Backend

1. Зайдите в Coolify.
2. Откройте нужный **Project** (например "My first project").
3. Выберите окружение **Production** (или то, где у вас api.allesinda.com).
4. В списке ресурсов найдите **Backend** (Allesinda, URL `https://api.allesinda.com`) и нажмите на него.

---

## 3. Проверить источник кода (Source)

1. В карточке Backend найдите блок **Source** / **Repository** / **Git**.
2. Убедитесь, что указан **правильный репозиторий** и **ветка** (например `main`).
3. Если есть кнопка **Refresh** / **Sync** — нажмите, чтобы Coolify подтянул последние коммиты.

---

## 4. Очистить кэш сборки и задеплоить заново

1. Найдите раздел **Build** / **Deploy** / **Build Options**.
2. Включите опцию вроде:
   - **Clear build cache**, или  
   - **Rebuild without cache**, или  
   - **No cache**, или  
   - **Clean build**
3. Сохраните настройки, если нужно.
4. Запустите **Deploy** / **Redeploy** / **Restart & Rebuild** для приложения Backend.
5. Дождитесь окончания сборки и запуска (логи должны пройти без ошибок).

Так вы гарантированно соберёте образ с актуальным кодом, а не со старым кэшем.

---

## 5. Проверить после деплоя

1. Откройте в браузере:
   - `https://api.allesinda.com/`
   В ответе может быть поле `"api_prefix"` — это нормально (если не задавали префикс, его не будет).
2. Откройте:
   - `https://api.allesinda.com/health`
   Должно быть: `{"status":"healthy", ...}`.
3. Проверьте новый маршрут (без авторизации будет 401, а не 404):
   - Откройте: `https://api.allesinda.com/chat/unread/count`  
   Ожидается ответ **401 Unauthorized** (или JSON с ошибкой авторизации), а **не 404 Not Found**.  
   Если 404 — маршрут всё ещё не попал в деплой.

---

## 6. Если в Coolify у Backend задан путь (Path / Base path)

Если в настройках приложения Backend указан путь, например **`/api`** (так что API доступно по `https://api.allesinda.com/api/...`):

1. В **переменных окружения Backend** добавьте:
   - Имя: `API_PREFIX`  
   - Значение: `/api`
2. В **переменных окружения Frontend** задайте:
   - Имя: `NEXT_PUBLIC_API_URL`  
   - Значение: `https://api.allesinda.com/api`  
   (без слэша в конце.)
3. Сохраните и задеплойте **сначала Backend**, потом **Frontend** (пересборка фронта обязательна, т.к. `NEXT_PUBLIC_*` вшивается при сборке).

Если пути в настройках нет — оставьте `NEXT_PUBLIC_API_URL=https://api.allesinda.com` и не задавайте `API_PREFIX`.

---

## 7. Итог

- **404 уходят**, когда на api.allesinda.com крутится **новая** версия бэкенда с маршрутами `/chat/unread/count` и `/media/me/{media_id}`.
- Для этого: **запушить код** → в Coolify **очистить кэш сборки** → **сделать Redeploy Backend**.
- Если у вас префикс `/api` — дополнительно выставить `API_PREFIX` и `NEXT_PUBLIC_API_URL` как выше и пересобрать фронт.

После этого удаление фото в галерее и бейдж непрочитанных сообщений должны заработать.
